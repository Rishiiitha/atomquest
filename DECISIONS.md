# Decisions and explicit scope cuts

- **Fresh scaffold:** the workspace was empty. The implementation starts in this repository and keeps the requested module layout.
- **Synthetic evidence only:** no compatible purifier or RO run-to-failure dataset was obtained. Direct public-source probes failed DNS resolution in this environment; candidate metadata is not treated as data. See `results/public_fetch.json` and `docs/DATA.md`.
- **Estimator implementation:** use a local two-state health/rate Kalman filter plus scikit-learn `HistGradientBoostingRegressor` residuals. The requested XGBoost and SHAP path was cut because those packages were not available locally and no SHAP explanation is validated. B1 uses the same light model family on raw features. Models export as joblib; ONNX is cut.
- **Learned stages:** RUL models cover sediment, UF, carbon, and RO. UV and alkaliser remain usage-based twin states and are not presented as learned forecasts. Carbon confidence is low because the product feature uses litres and an assumed chlorine concentration.
- **Physics scope:** the simulator solves a lumped RO flow balance, current-to-pressure line, Darcy pressure drop, and Thomas-style carbon breakthrough. Prefilter resistance grows according to a configured life-fraction proxy; the standalone cake-mass helper is not integrated into this daily simulator. No Hermia kinetic blend, independent capture-efficiency fit, stochastic damage random walk, UF flush recovery, or tank-level control is claimed. See `docs/PHYSICS.md`.
- **Telemetry and scenario scope:** the twin is daily aggregated. It does not model morning/evening draw events, pump cycle counts, sensor dropouts, quantization, clock jitter, or true raw high-frequency traces. OOD perturbations are synthetic examples, not a calibrated distribution.
- **Attribution:** controlled signatures are generated under simplified fixed-duty and speed-regulated assumptions. A trained cause classifier was cut because simulated signatures cannot establish real-device separability; sediment and UF remain explicitly confounded.
- **Product stack:** use procedural React Three Fiber geometry, self-hosted font assets, and custom CSS. Tailwind utility classes were cut because the interface is authored with a consistent local token system. The Three.js runtime is split into a lazy chunk; browsers that lose WebGL switch to the labeled SVG schematic. Headless Chromium verified the recovery path, but native GPU rendering, target-device frame-rate, and Lighthouse scores remain unmeasured.
- **Sequence baseline:** GRU/1D-CNN was cut. The grouped daily cohort and gradient-boosted baselines cover the first prototype evidence loop.
- **Platform:** GNU Make was absent at start; a Makefile plus Windows PowerShell scripts are included. The pnpm 11 workspace uses `pnpm-workspace.yaml` settings and pins compatible Motion dependencies. OpenAPI types, production build, full cohorts, Chromium screenshots, and four Playwright gates completed. Direct local HTTP checks passed for health, scenarios, evidence, simulation, what-if, and CSV ingest; a live WebSocket check passed pause/seek/resume/event injection. Starlette's thread-backed `TestClient` still stalls in this managed Windows runtime, and browser-to-live-API plus clean-clone setup/demo checks remain unverified.
- **Business impact:** fleet policy results are simulated counts over a configured horizon with exposed assumptions. In the full run, the FilterTwin policy used fewer replacements but also produced more simulated failures than the fixed schedule. No customer costs, measured savings, or deployed replacement policy are claimed.
